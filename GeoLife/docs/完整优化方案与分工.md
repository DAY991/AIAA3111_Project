# GeoLife 组合退化完整优化方案与分工

采用现有冻结协议 `degradation_config.yaml`（v1.0.0），完成“采样稀疏 × 新增坐标噪声”下 RF 与 GRU 的配对评估、特征分析和场景解释。成员 A 负责模型实验与结果接口；成员 B 负责特征漂移、模型依赖分析和文献支持。以下是执行方案，实际完成状态以运行日志、模型凭据和输出表为准。

研究问题是：**在相同干净训练数据和用户隔离条件下，两个既定流程在什么组合退化条件下表现更好，差距是否反转；性能变化伴随什么覆盖损失和特征变化？** 不预设 GRU 胜出，不以“首次同时研究降采样与噪声”作为贡献。

## 一、共用阶段：先锁定可比性

### 步骤 1：确认研究范围与协议

| 项目 | 本轮固定设置 |
|---|---|
| 数据与标签 | 已处理 GeoLife；walk / bike / bus / car / subway，taxi 并入 car |
| 参考窗口 | 连续同标签段内 120s 非重叠窗；至少 10 点、最大断档不超过 30s |
| 主网格 | ds0 / ds5 / ds10 × n0 / n5 / n10 / n20，共 12 个条件、24 个模型条件 |
| ds0 含义 | 保留原生不规则采样，不称为“1s 数据” |
| 时间抽稀 | 相对窗口首点分桶，每桶保留首点；不保证相邻保留点至少相隔指定秒数 |
| 坐标扰动 | x、y 独立零均值高斯；n 表示每轴标准差 σ，单位米 |
| 退化顺序 | 参考窗副本 → 时间抽稀 → 新增坐标噪声 → 可用性检查 → 提取特征 |
| 噪声配对 | 共同使用 `deployment_protocol.py`；噪声由 seed、持久 window_id、原窗点位置确定 |
| 训练与测试 | LOUO；每折训练一次干净 RF、GRU，各条件只退化该折测试用户 |
| 训练参数 | 沿用 YAML：RF 300 棵树、balanced；GRU hidden64、序列128、15 epoch；训练 seed=0 |
| 噪声重复 | 全主网格 seed=0；ds10_n10 另跑 seed=1、2；不重复确定性 clean 或空的压力条件 |
| 30s 压力边界 | 保留四个噪声条件的覆盖率；不可用时 F1 留空，状态为 `no_usable_windows` |

本轮不临时降低最少点数、不改变窗口长度、不加入新模型或训练增强。必要的新实验另设协议版本和输出目录，不覆盖 v1.0.0。

### 步骤 2：固定窗口、支持集与用户折

成员 A 运行准备阶段，并将输入、配置、实现及产物哈希交给 B。B 读取同一参考 manifest 和公共支持标记，不能从子集重新编号 window_id，也不能自己实现另一个“相同参数”的噪声函数。

已经完成的全量覆盖率预实验提供以下基准，后续准备结果应能对齐：

| 采样档 | 可用参考窗 | 覆盖率 | 有可用窗口的用户 |
|---|---:|---:|---:|
| ds0 | 90,120 | 100.00% | 54 |
| ds5 | 84,195 | 93.43% | 52 |
| ds10 | 71,941 | 79.83% | 48 |
| ds30 | 0 | 0.00% | 0 |

12 个主条件的共同可用集为 71,941 窗口、48 位用户。完整训练评估仍建立 54 个 LOUO 折：每折训练使用其余用户的全部干净可用参考窗；公共集主指标只覆盖有公共可用窗的 48 位用户。公共集不用于缩减训练数据。

两种支持集分别报告，不能混为同一实验：

- `cohort=common`：主网格和 B 的四格分析均使用固定的 71,941 个窗口；RF/GRU、不同条件之间逐窗配对。
- `cohort=condition`：各条件自己的可用窗；用于展示实际覆盖与条件内性能，不能把不同幸存集上的分数差直接当退化效应。

公共集偏向采集较完整的记录，其结果不能代表所有出行窗口。覆盖率分母始终是 90,120 个干净可用参考窗，另报逐类、逐用户覆盖率。

### A4：整理指标与配对质检

正式 `grid_results.csv` 是宽表，每行由条件、噪声种子和 cohort 确定，同时包含 RF/GRU Macro-F1、Accuracy、逐类 F1、覆盖率和差值。固定五类顺序及 `zero_division=0`。主分数是拼接全部留出用户预测后计算的 OOF Macro-F1，**不是**逐用户 Macro-F1 的算术平均。

依次完成以下检查：

1. 主表过滤 `scope=full_louo`、`cohort=common`、`noise_seed=0`；12 格都计分 71,941 个相同窗口，两个模型没有缺预测。
2. 主 grid、覆盖表、模型与预测具有兼容的输入和协议来源。相同采样档的覆盖率不随 σ 或噪声种子变化。
3. 逐类检查覆盖与 F1，尤其防止只剩少量类别时总体分数造成误读。公共集类别窗口数应与准备表一致。
4. 由 RF/GRU 同窗配对差得到 `GRU−RF`；差值乘 100 表示百分点，不称相对百分比增益。
5. 对 ds10_n10 报 3 次噪声实现的均值、样本标准差和种子数。其余单种子结果不编造标准差。训练种子固定，本表不衡量训练随机性。
6. 检查反转或非单调格点的支持集、处理顺序、噪声尺度和特征计算。实现正确时保留现象并交给 B，不把“更严重退化反而更好”自动视为错误。

## 三、成员 B：可并行推进的漂移、模型依赖与场景解释

B 不需要等待 A 完成全部模型实验才开始，但不是“完全无依赖”。准备产物是共同前置条件；模型依赖分析还需要 A 的可验证 RF 逐折缓存。

**当前可运行的是 A 的 prepare/evaluate/figures 入口。下述 B 专用特征表、联合置换和文献表尚需 B 实现与整理；这里规定算法、输入输出和验收，不将不存在的脚本写成可运行命令。**

### B1：读取共享产物，建立四格分析清单

固定代表条件为：

| 条件 | 作用 |
|---|---|
| ds0_n0 | 原生采样、无新增噪声；四格共同基线 |
| ds10_n0 | 仅采样稀疏 |
| ds0_n20 | 仅新增噪声 |
| ds10_n20 | 采样稀疏与噪声组合 |

四格均使用同一 `common` 窗口集合，不用 ds0 的 90,120 窗与 ds10 的 71,941 窗混比。读取 `reference_manifest.csv` 与 `support.npz`，按照 manifest 原行序索引支持标记，选中公共集后保留原 window_id。

用共享 `degrade_window`、noise_seed=0 和持久 window_id 生成四格窗口。噪声按完整原窗点位置配对，再选择抽稀保留点，不能对抽稀后的点重新编号生成噪声。特征使用现有 `features.window_statistical_features`，非有限数的处理与 A 一致，RF 输入列顺序严格等于 `CORE_A_FEATURES`。

输出建议：`feature_drift_by_feature.csv`、`feature_drift_by_group.csv`，大特征缓存本地保存，不把全部坐标或逐窗巨表塞入 Git。

**验收：** 四格 window_id 与标签逐行一致；特征重算可重现；抽查可与 A 的对应预测前输入对齐；对所有四格仍满足可用性规则。

### B2：先独立做配对特征漂移

这一步不依赖已训 RF。对每个公共窗口比较退化特征和该窗 ds0_n0 特征，至少报告原单位的配对差值、绝对差的中位数及四分位范围，再按特征组汇总。按类别与用户补充分解，检查是否只有部分用户驱动总体结果。

若需要跨量纲比较，可对每个留出用户，用其余训练用户干净特征的 IQR 标准化差值；IQR 为零时使用事先约定的训练标准差，仍为零的列标记为常数而不除零。标准化规则与基准都不能由该测试用户或退化结果来选择。组级汇总使用事先约定的标准化尺度，不将秒、点数等原单位差直接相加。原单位结果同时保留，不用一个标准化总分代替所有细节。

B 可自行从共享干净窗口提取训练尺度，也可复用 A 已生成且指纹相同的干净特征缓存。此分析只改变解释表，不更新模型、缩放器或特征选择。

**验收：** 四格同窗配对；单位明确；常数列和非有限值规则有记录；输出能区分差分运动量变化与采样时间/点数变化。特征漂移大并不自动表示该特征导致 F1 下降。

### B3：按现有 17 列冻结六个特征组

| 组名 | 现有特征列 |
|---|---|
| 速度 | mean_speed、std_speed、max_speed、median_speed、q25_speed、q75_speed |
| 加速度 | mean_acc、std_acc、max_acc |
| 方向变化 | mean_heading、sum_heading、std_heading |
| 距离 | path_length |
| 采样与时间 | duration、n_points、mean_gap |
| 停留比例 | stop_ratio |

组名只用于解释，不能增加未经训练的特征或调整 RF 输入顺序。`duration` 是实际首末点时间差，不能直接当成固定的窗口标签 120s。`stop_ratio` 由速度阈值派生，与速度组相关；跨组相关仍会影响解释。

### B4：收到逐折 RF 后做联合 permutation importance

1. 从 A 交接的正式 `run_<hash>/folds/<user>/rf.joblib` 加载该测试用户对应的 RF。核对 `models.json` 中训练用户列表、运行 ID 和 RF 哈希；该用户不在训练中。禁止用全数据训练的一个 RF 解释全部测试用户。
2. 在该用户公共窗口上生成四格特征，以不置换的输入先预测。汇总已具备模型用户的 OOF 预测，基线应与 A 对应条件、公共支持、主 seed=0 的结果一致。
3. 对每一特征组、每次置换重复，在该 held-out user 的窗口行内生成一个行排列。该组所有列使用**同一个行排列**，其余列不变；不在不同用户之间交换行。
4. 同一用户、组和重复的排列在四个条件中复用，使重要性变化可配对。B 将置换基种子、重复编号、用户标识的稳定派生规则写入分析 manifest，不使用进程间不稳定的 Python `hash()`。建议预先固定 10 次置换重复；这是 B 的分析随机性，不能改 YAML 的训练或噪声种子。
5. 每个留出用户均用自己的 RF 预测置换输入，然后拼接所有公共支持用户的 OOF 预测，再计算固定五类 Macro-F1。重要性定义为 `PI(group, condition, repeat) = F_original(condition) - F_permuted(condition, group, repeat)`。
6. 对重复计算均值、样本标准差和次数，保留负重要性；输出原始基线 F1、置换后 F1、计分窗数、用户数、模型来源和支持集合身份。逐用户表作为诊断补充，不把“逐用户平均 F1”和 A 的 pooled OOF F1 混为同一指标。
7. 模型尚未齐全时可增量处理已交接的折，但明确标记 partial 和已完成用户列表。最终表涵盖公共支持的全部 48 位用户；公共集为空的其余折不为 B 产生有效分数。

输出建议：`group_permutation_importance.csv`、`group_permutation_summary.csv`、`member_b_analysis_manifest.json`。B 应实现并记录自己的可执行入口后再补复现命令，不绕过 A 的缓存校验。

**并行资源约定：** A 的 RF 当前使用 `n_jobs=-1`，可能占满 CPU。B 在自己加载的 RF 内存副本上设 `rf.n_jobs=1`，资源允许时最多用 2；不改写 A 的模型文件，不同时并行多个折和多个置换任务。逐折处理、完成后释放模型，避免把所有 RF 一起载入内存。A 训练 RF 时优先运行文献工作或低并发漂移分析；需要增加并发前双方确认资源余量。B 的线程设置与置换重复数写入其分析记录，防止争用 32 核导致 A 的计时和训练受明显影响。

**解释要求：** 联合置换保留组内列的关联，但可能破坏与组外列的关系，因此是“这个既定模型对这些输入的依赖”证据。不能将多个相关单列的 importance 相加当作组效应或因果贡献。严重退化时模型已接近失效，重要性可能整体接近零；不能据此断言特征没有信息。结合 B2 的配对漂移和 A 的绝对性能解释。[scikit-learn 官方说明](https://scikit-learn.org/stable/modules/permutation_importance.html)

### B5：分离主效应与交互，形成有限度的解释

对模型 m，在公共支持上定义 `F_m(ds,n)` 为对应 Macro-F1。以四格为例：

```text
采样下降 D_ds = F(0,0) - F(10,0)
噪声下降 D_n  = F(0,0) - F(0,20)
组合下降 D_dn = F(0,0) - F(10,20)

I(10,20) = F(10,20) - F(10,0) - F(0,20) + F(0,0)
         = D_ds + D_n - D_dn
```

- I<0：在 F1 尺度上，组合损失大于两种单独损失之和，可描述为超加性下降。
- I>0：组合损失小于两种单独损失之和，可描述为缓和或抵消。
- I≈0：接近加性；是否可视为接近零需结合重复或区间，不凭小数点肉眼设显著性。

A 的 `interaction_contrasts.csv` 按相同公式提供 ds5/ds10 与各非零噪声的结果。B 将四格解释与该表核对，不能拿条件自身幸存集计算交互，也不能混合种子或运行 ID。

对六组 importance 同样可报告“四格之差”，但需明确它是模型依赖变化的描述性对比。F1 是非线性且有界指标，该对比不是自动成立的物理交互或因果识别。

允许出现抽稀缓和独立噪声影响的情况：等间隔简化模型中，位置白噪声对每轴差分速度的标准差约为 `sqrt(2) × σ / Δt`。抽稀一方面损失运动细节，另一方面可能减小该差分噪声；不能预先把所有组合写成“1+1>2”。

### B6：完成文献核查和 12 格启发性场景表

B 可以与 A 训练并行完成这一部分。对每个文献填写作者、题名、年份、DOI/主来源链接、实际测量对象、误差定义和本项目可用范围。

- Burkhard et al. 2020 已研究空间精度与采样率变化，也比较既有检测方案；不能说它只给阈值、不比较架构。[作者机构记录](https://www.research-collection.ethz.ch/entities/publication/d43a9f92-a6fc-4185-9884-795240e4847b)
- Wang et al. 2024 使用真实手机信令数据，其定位频率和窗口尺度不同；可支持问题背景，不能直接搬用性能阈值。[期刊原文](https://xnjdxb.swjtu.edu.cn/cn/article/doi/10.3969/j.issn.0258-2724.20220136)
- Weng et al. 2023 可支持城市 NLOS 与多径误差背景；其定位精度数值不是本实验每轴 σ 的校准值。[PolyU 作者机构记录](https://research.polyu.edu.hk/en/publications/characterization-and-mitigation-of-urban-gnss-multipath-effects-o/)

以下映射是报告的起始表，B 应保留“启发性压力情景”限定，并逐条标注文献支持范围。所有格点的 σ 均是**叠加在已含原始误差的观测轨迹上的新增扰动**；n0 也不意味着真实坐标无误差。

| 格点 | 采集与新增扰动情景 | 可讨论的现实关联 |
|---|---|---|
| ds0_n0 | 原生采样，无新增扰动 | 数据质量基线；不是理想真值定位 |
| ds0_n5 | 原生采样，弱新增扰动 | 较密集采集下的轻度位置抖动压力 |
| ds0_n10 | 原生采样，中等新增扰动 | 采样保留时，位置质量变差的压力 |
| ds0_n20 | 原生采样，强新增扰动 | 城市遮挡/反射问题启发的位置扰动压力 |
| ds5_n0 | 5s 时间桶抽稀，无新增扰动 | 中等频率采集策略，单独检验时间稀疏影响 |
| ds5_n5 | 5s 抽稀，弱新增扰动 | 降低采集频率并伴轻度位置抖动 |
| ds5_n10 | 5s 抽稀，中等新增扰动 | 中等采集频率与位置退化同时存在 |
| ds5_n20 | 5s 抽稀，强新增扰动 | 中等频率采集中的强定位扰动压力 |
| ds10_n0 | 10s 时间桶抽稀，无新增扰动 | 更稀疏的后台/定时采集策略启发的压力 |
| ds10_n5 | 10s 抽稀，弱新增扰动 | 稀疏采集与轻度位置抖动组合 |
| ds10_n10 | 10s 抽稀，中等新增扰动 | 稀疏采集与位置质量下降组合；关键噪声重复格 |
| ds10_n20 | 10s 抽稀，强新增扰动 | 低频采集与城市定位困难同时出现的简化压力 |

不要将这些行写成“10s 就是省电模式”“20m 就是城市峡谷”或“30s 就是手机信令”。本项目没有测量手机功耗、系统后台策略或真实建筑环境；真实误差还含偏置、时间相关、重尾、遮挡和缺失。

二维独立同方差噪声的新增径向 RMSE 是 `sqrt(2) × σ`，95% 半径约 `2.448 × σ`。因此 n20 的新增径向 RMSE 约 28.3m，不能直接对标文献中的 15m 或 20m“定位精度”。未核实的“节电33%、精度仅降0.6%”不写入正式表；未经核实的题名、作者或 DOI 不进入参考文献。

输出建议：`scenario_mapping.csv`、`literature_evidence.csv`，以及包含图表依据的讨论段落。可以说“保持原有两个模型和当前采集限制时的相对性能参考”，不能宣称实验验证了真实手机部署可用性。

## 六、统计、泄漏与结论边界

1. 测试用户不能参与模型拟合、类别权重、缩放、调参或特征选择。本轮沿用冻结超参数，没有开展新的测试集驱动调参。若未来调参，应在训练用户内部做分组验证。
2. 噪声种子标准差只反映固定模型与测试用户上的模拟噪声实现差异；置换标准差只反映固定输入和模型下的置换随机性。两者不能当训练稳定性、跨用户泛化置信区间或统计显著性。
3. bootstrap 若作为增强，应按用户整组重采样并同时保留所有模型/条件预测配对；相邻窗不能假定独立。固定OOF预测的区间也不能涵盖重训和训练样本选择的全部不确定性。
4. 共同窗口保证配对，但造成完整记录的选择效应；同时报告被排除的窗口和用户，不能把主表当全体轨迹的部署表现。
5. 两流程同时改变特征聚合方式、模型结构和容量，比较的是既定 RF 与 GRU 流程，不能单独证明“所有序列表示优于统计表示”。
6. 两个模型绝对性能较低时，即使其中一个占优，也不能据此确认可部署。不人为规定一个未经任务验证的“F1可用阈值”。讨论相对优势和数据质量要求，保留失败和反转结果。
7. importance 是模型依赖证据，漂移是输入变化证据；二者和 F1 组合支持有限解释，不等于因果证明。不能因 importance≈0 断言该特征无信息。
8. 当前参考窗先按真实标签的连续同类段建立，属于利用已知标签保证窗口纯度的离线评估。真实部署时并不知道方式切换点，因此本实验不是端到端的在线切段加识别验证；自动分段属于后续独立研究。
